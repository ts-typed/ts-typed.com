# Documentation versioning

The documentation line follows `major.minor`, never patch, and is independent of each package's own npm version. The `0.1` line is the current default: it documents the latest release of `@ts-typed/core`, `@ts-typed/nestjs`, `@ts-typed/express`, and `@ts-typed/validators`, regardless of which `major.minor.patch` each package has actually published (core, for example, is on the `0.7.x` npm line while still documented under the `0.1` documentation line). Check each package's `CHANGELOG.md` — linked from the [Changelog](/changelog) page — for its real current version.

When a package reaches a new minor or major line, add that line to `src/app/docs-versions.ts`, preserve the existing line, set its `directory`, and add version-specific content under `public/docs/<line>/<language>/`. Patch releases update the current line only. The three package pages share the selected documentation line, so compiler, NestJS, and validators stay aligned without pretending that patch releases are separate documentation versions.
